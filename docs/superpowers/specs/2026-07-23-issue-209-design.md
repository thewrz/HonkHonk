# Issue #209: Sound-or-Macro Slot Persistence

## Goal

Give the fixed 20-slot map a versioned state-layer contract that can persist
either a sound path or a macro ID without changing existing sound assignment,
lookup, activation, or UI behavior.

## Persistence contract

The canonical `slots.json` format is version 1:

```json
{
  "version": 1,
  "slots": [
    "/sounds/honk.wav",
    { "type": "macro", "id": "a1b2c3d4e5f67890" },
    null
  ]
}
```

- The `slots` array contains exactly 20 entries.
- A sound remains a bare JSON string.
- A macro is an object tagged with `"type": "macro"`.
- An empty slot is `null`.
- The legacy format is the existing unversioned array of 20 sound strings or
  nulls. It loads as writable version-0 data and is emitted as version 1 on the
  next save.
- Unknown versions, object variants, fields, invalid IDs, and shapes are
  unsupported. Loading them yields an empty read-protected map so the source
  file cannot be overwritten by this version of HonkHonk.
- A missing file yields an empty writable map.

## Data structures and interfaces

```rust
pub enum SlotContent {
    Sound(PathBuf),
    Macro(String),
}

pub enum MacroIdError {
    Empty,
    TooLong { length: usize, max: usize },
    ControlCharacter,
}

pub struct SlotMap {
    slots: [Option<SlotContent>; 20],
    writable: bool,
}
```

Existing sound APIs retain their behavior:

```rust
get(idx) -> Option<&PathBuf>
set(idx, path)
clear(idx)
slot_for(path) -> Option<u8>
```

New content and macro APIs are:

```rust
content(idx) -> Option<&SlotContent>
set_macro(idx, id) -> Result<(), MacroIdError>
macro_id(idx) -> Option<&str>
slot_for_macro(id) -> Option<u8>
```

Macro IDs are valid when their UTF-8 representation is nonempty, at most 255
bytes, and contains no control characters. Their current 16-character hash
shape is deliberately not part of this contract.

## Invariants

1. A `SlotMap` always contains exactly 20 slots.
2. A slot contains at most one content value.
3. Sound access and lookup never match macro content; macro access and lookup
   never match sound content.
4. Setters and clearing outside `0..20` are no-ops and never panic.
5. Invalid macro IDs never enter a `SlotMap`.
6. Every successful save emits version 1 and exactly 20 slot entries.
7. Every successfully loaded legacy assignment retains its sound path exactly.
8. Malformed, unsupported, unreadable, or future-version files are never
   overwritten through the loaded map.
9. A missing file remains a writable default.
10. The outer persisted sound and object shapes are disjoint; object variants
    require a recognized internal type tag.

## Change map

- `src/state/slots.rs`: in-memory model, validation, and public accessors.
- `src/state/slots/persistence.rs`: versioned/legacy Serde DTOs, load, save, and
  read-protection behavior.
- `src/state/slots/tests.rs`: API and persistence boundary tests.
- `src/state/error.rs`: slot-specific unsafe-overwrite error variant.
- `src/state/mod.rs`: export `SlotContent` and `MacroIdError`.

No app dispatch, hotkey behavior, stale-reference cleanup, slot-manager
rendering, macro UI, or macro persistence changes are included.
