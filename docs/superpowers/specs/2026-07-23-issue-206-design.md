# Issue #206 — Persist Assigned Tile Graphic References

Date: 2026-07-23 · Status: approved

## Why

Per-sound tile graphics need a stable persistence boundary before image selection, asset copying,
thumbnail generation, or rendering. This slice stores only an application-owned filename. It does
not persist an external path or reopen the canvas-rendering decisions in ADR-009.

## Data Shapes

- `SoundMeta.assigned_graphic: Option<GraphicAssetRef>` stores the optional assignment alongside
  favorites, volume, and the display-name override.
- `GraphicAssetRef` wraps one validated UTF-8 filename component. Its inner string is private, and
  construction is available only through its validating constructor or validated deserialization.
- `GraphicRefError` is the typed validation error returned when a caller attempts to construct an
  invalid reference.
- The sound-metadata envelope version advances from v1 to v2. v1 and legacy unversioned data load
  with `assigned_graphic = None`; all successful saves emit v2.

The future asset-copying layer will generate the filename and store the corresponding file beneath
`$XDG_DATA_HOME/honkhonk/tile-graphics/`. Original external paths never enter this state model.

## Interfaces and Contracts

- `GraphicAssetRef::new(filename) -> Result<Self, GraphicRefError>` validates an owned filename.
- `GraphicAssetRef::as_str() -> &str` exposes the opaque filename without exposing unchecked
  construction.
- `SoundMetaStore::assigned_graphic(id) -> Option<&GraphicAssetRef>` reads an assignment.
- `SoundMetaStore::set_assigned_graphic(id, reference)` sets a validated assignment.
- `SoundMetaStore::clear_assigned_graphic(id)` clears one assignment and prunes the custom metadata
  entry when every field has returned to its default.

A valid reference is nonempty, no longer than 255 UTF-8 bytes, and exactly one ordinary filename
component. `/`, `\`, control characters, `.`, and `..` are rejected. Consequently absolute paths
and parent traversal cannot cross the state boundary.

## Persistence Compatibility

- v2 is the only emitted envelope version.
- v1 envelopes migrate in memory; their existing customizations and first-seen timestamps survive,
  and every graphic assignment defaults to `None`.
- Legacy top-level sound-ID maps remain supported and likewise default assignments to `None`.
- Any other explicit envelope version is unsupported.
- Invalid v2 graphic references, corrupt JSON, malformed envelopes, and unsupported versions load
  as empty, read-protected stores. A subsequent save refuses to overwrite the source file.

## Invariants

1. Every in-memory and persisted `GraphicAssetRef` has passed the same filename validation.
2. A persisted graphic reference never identifies an absolute path, parent traversal, or more than
   one filename component.
3. A valid assignment survives a v2 save/load round trip without changing its filename.
4. v1 and legacy metadata survive migration with `assigned_graphic = None`.
5. Invalid, corrupt, or unsupported persisted input can never be overwritten through the loaded
   store.
6. Clearing the only nondefault field removes the custom metadata entry exactly as before.
7. The change does not select, copy, decode, thumbnail, or render an image.
