# Issue #196 — Shared Filtering and Type-to-Filter Activation

Date: 2026-07-20 · Status: approved

## Why

HonkHonk needs one reusable filter controller for the main sound grid and later list views. The
main grid keeps click-to-focus search while gaining type-to-filter: an otherwise unhandled printable
keypress focuses the search field and becomes the first query text.

Iced already reports whether a widget captured an event. That runtime signal is the source of truth
for protecting other text inputs; a manually maintained `text_entry_active` flag would duplicate
widget state and can become stale.

## Data Shapes

- `FilterState { query: String, had_focus: bool }` owns transient query and staged-Escape state.
- `Activation::{TypeToFilter, ClickOnly}` declares whether an active view may claim ignored
  printable keypresses.
- A compact activation context describes the active view and whether a blocking layer is visible.
- The shared search input has a stable Iced widget ID so the first type-to-filter message can return
  a programmatic focus task.

Filter state is never persisted and starts empty on every launch.

## Interfaces and Contracts

- `filter_items(items, query, haystacks)` is pure and returns borrowed items whose supplied fields
  contain the query case-insensitively. An empty query preserves input order and includes every
  item.
- `FilterState` methods own query replacement, insertion of produced keyboard text, and Escape
  staging. The first Escape after focus only consumes focus state; the next clears a non-empty
  query.
- The shared `search_bar` view accepts message-mapper callbacks instead of importing the app's
  concrete `Message` type.
- The event mapper emits type-to-filter input only for `KeyPressed.text` that is non-empty and
  printable, has no Control/Alt/Super modifier, and has Iced `event::Status::Ignored`.
- The app boundary accepts type-to-filter only when the current view uses `TypeToFilter` and no
  context menu, sound editor, macro editor, or visible effects drawer blocks the grid.
- The first accepted keypress updates the query and returns a focus operation for the shared search
  input. Once focused, the widget captures subsequent input and its normal `on_input` path updates
  the same `FilterState`.

## Main-Grid Migration

`HonkHonk.search_query` and `search_had_focus` become one `FilterState`. Existing category and
Favorites filtering composes with the shared query filter. Main-grid haystacks include:

1. customized display-name override;
2. original filename, including extension;
3. existing filename stem/name;
4. folder-derived category.

This preserves prior search behavior while making the shared function the only query-matching
implementation.

## File-Size Strategy

`src/app/mod.rs` is already far over the project limit, so this issue must not grow it. Put filter
event mapping, activation guards, app helper methods, and their tests in `src/app/filtering.rs`.
Changes in `app/mod.rs` are limited to module/message/state declarations and short delegation arms;
move existing search tests into the new module where practical.

## Spike

Before implementation, compile and manually exercise the smallest throwaway path proving that:

- a focused Iced text input marks printable key events captured;
- an unfocused printable key reaches `listen_with` as ignored;
- manually inserting the first text followed by the widget focus task does not duplicate or drop
  that character.

Revert all spike changes and retain only the findings before starting TDD.

## Invariants

1. Type-to-filter never claims a keypress already captured by another widget.
2. Control, Alt, and Super shortcuts never become filter text; Shift-produced text and Unicode do.
3. Blocking layers prevent activation even when the event was otherwise ignored.
4. The first accepted character appears exactly once and focuses the shared input.
5. Click-to-focus and direct input continue to work.
6. First Escape blurs/consumes focus state; second Escape clears; overlay Escape priority remains
   unchanged.
7. Filtering is transient, stable-order, and shared rather than reimplemented in app state.
