# Issue #208 — Conservative Dead Stereo Channel Repair

Date: 2026-07-23 · Status: approved

## Why

Some nominally stereo clips carry useful audio in only one channel. HonkHonk should center those
clips without changing ordinary stereo, quiet material, silence, or audio with a deliberately
asymmetric but non-dead channel.

The repair belongs at the complete decoded-PCM boundary. Both tile playback and macro playback use
`audio::decode`, while the decoded cache and PipeWire playback paths consume its result. Applying
the transform once there guarantees that cached and uncached playback share the same samples and
keeps analysis off the real-time audio thread.

## Data and Thresholds

The transform receives the decoded interleaved `f32` sample slice, sample rate, and channel count.
It allocates no replacement buffer and reports whether it changed the slice.

- A channel is dead when its absolute peak never exceeds -80 dBFS:
  `10^(-80 / 20) = 0.0001`.
- A candidate live channel is meaningful when at least one contiguous block of at most 50 ms
  has RMS at or above -50 dBFS: `10^(-50 / 20) ≈ 0.0031622777`.
- A clip shorter than 50 ms is evaluated as one block. Longer clips use complete 50 ms windows,
  including the window ending at the final frame.
- Threshold comparisons are inclusive: exactly -80 dBFS is dead and exactly -50 dBFS is live.

Peak detection is deliberately stricter than the live-channel RMS gate. The maximum block RMS
requires more than a lone near-zero lane, while the whole-clip peak check preserves any opposite
channel whose content rises above the conservative dead threshold.

## Interface and Algorithm

`audio::channel_repair::repair_dead_stereo_channel(samples, sample_rate, channels) -> bool` is a
focused pure transform.

1. Return `false` without mutation unless the buffer is nonempty, the sample rate is nonzero, the
   channel count is exactly two, the sample count is frame-aligned, and every sample is finite.
2. Compute the absolute peak of each interleaved lane over the complete clip.
3. Continue only when exactly one lane is at or below the dead-channel threshold.
4. Compute the maximum block mean-square energy of the other lane and compare it with the squared
   live RMS threshold.
5. If live, copy each live sample into the dead lane in place and return `true`. Never average,
   attenuate, normalize, or change the interleaving.

The known accepted limitation is that a deliberately hard-panned clip with digital silence in the
opposite lane is mathematically indistinguishable from a broken stereo file and will be repaired.

## Invariants

1. Mono, multichannel, empty, odd-length, zero-rate, and non-finite buffers are byte-for-byte
   unchanged.
2. Silence and clips where neither channel reaches the live RMS threshold are unchanged.
3. Ordinary stereo and any opposite lane whose peak exceeds -80 dBFS are unchanged.
4. A repair occurs only when exactly one channel is dead and the other is live.
5. After repair, every frame contains two copies of the original live sample.
6. Repair preserves sample count, order, amplitude, sample rate, channel count, and decoded
   duration.
7. Analysis and repair allocate no PCM-sized buffer and never run on the PipeWire real-time thread.
